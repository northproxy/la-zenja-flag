# La Zenia — статус пляжа для nadadeneg.com/flag

Готовая статическая страница на русском, сборщик Ambumar и GitHub Actions.
На хостинге не нужны Python, Node.js или база данных: вычисления выполняет GitHub.
Публикация пока не выполнена: нужны настройки вашего FTP-доступа.

## 1. Подготовьте каталог в World4You

1. Откройте https://my.world4you.com/ и выберите пакет, обслуживающий nadadeneg.com.
2. Найдите настройки FTP-доступа и каталог сайта (названия разделов зависят от панели).
3. В каталоге, из которого обслуживается www.nadadeneg.com, создайте папку `flag`.
4. Подготовьте имя FTP-сервера, FTP-логин и FTP-пароль. Используется именно FTP-пароль, не пароль от всей панели.
5. Если панель позволяет, ограничьте этот FTP-доступ созданной папкой `flag`.

Важно: URL `/flag/` не сообщает нам путь в FTP. Путь зависит от настроек аккаунта.
Проверьте его в файловом менеджере или FTP-клиенте. Не подставляйте наугад `/htdocs/flag` или `/www/flag`.
Если FTP-пользователь уже ограничен самой папкой flag, его целевой путь может быть `/`.

Загрузчик подготовлен для **FTP с явным TLS (FTPS), порт 21, пассивный режим**.
Имя сервера берите из панели World4You, а не автоматически `www.nadadeneg.com`.
Проверьте доступность этого режима для вашего пакета. Если указан только SFTP,
загрузчик нужно адаптировать — это другой протокол. Проверка сертификата включена;
не отключайте её при ошибке, проверьте имя сервера.
Точное подключение к вашему аккаунту не проверено, так как его данные не предоставлены.

## 2. Создайте репозиторий GitHub

1. Создайте репозиторий, например `la-zenia-flag`, с основной веткой `main`.
2. Распакуйте архив. В корень репозитория загрузите содержимое папки `beach-flag`,
   а не сам ZIP и не дополнительный вложенный каталог `beach-flag`.
3. В корне должны быть `site`, `scripts`, `tests`, `README.md` и `.github`.
4. Если скрытая папка `.github` не попала при загрузке через браузер:
   нажмите **Add file → Create new file**, задайте имя `.github/workflows/update.yml`
   и вставьте содержимое файла из архива. Без него автоматизация не появится.

В проекте нет внешних Python-зависимостей. JavaScript встроен в HTML;
отдельный `.js` скачивать и загружать не требуется.

## 3. Добавьте четыре GitHub Secrets

Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.

| Имя | Значение |
|---|---|
| `W4Y_FTP_HOST` | Имя FTP-сервера из панели, без `ftp://`, пути и порта |
| `W4Y_FTP_USER` | FTP-логин |
| `W4Y_FTP_PASSWORD` | FTP-пароль |
| `W4Y_FTP_DIR` | Проверенный путь к папке flag с точки зрения этого FTP-пользователя |

Не записывайте пароли в исходные файлы. Загрузчик работает только с тремя файлами
в выбранном каталоге: `index.html`, `favicon.svg`, `status.json`. Эти имена будут
перезаписаны. Остальные файлы не удаляются. Для обновления используются временные
файлы с суффиксом `.upload` и переименование после окончания передачи.

## 4. Первый запуск

1. Откройте **Actions → Update beach flag → Run workflow → main → Run workflow**.
2. Дождитесь успешного завершения. При первом push до добавления Secrets запуск
   может завершиться ошибкой — после настройки просто запустите его вручную.
3. Откройте https://www.nadadeneg.com/flag/ . Домен должен иметь действующий HTTPS.
4. Проверьте строку «Попытка проверки». «Нет данных» при свежем времени — допустимый
   результат: таблица спасателей может быть пустой.
5. На iPhone: Safari → Поделиться → На экран «Домой».

Расписание: каждый час на 7-й, 22-й, 37-й и 52-й минутах (круглосуточно).
Это примерно 96 запусков в сутки. GitHub может задерживать задания; расписание
работает из основной ветки. Следите за квотой Actions, особенно для private-репозитория.
В публичных репозиториях расписание может отключаться после длительного отсутствия
активности: проверьте Actions, если обновления остановились.

Кнопка на странице перечитывает опубликованный JSON, а не запускает GitHub Actions.
Пока страница открыта, JSON также перечитывается раз в минуту и при возвращении во вкладку.
GitHub-токен на странице не нужен и не хранится.

## Что считается достоверным

Источник: https://ambumar.com/estado-de-playas/
Таблица: https://ambumar.app/estados-playas.php
Выбирается только строка CALA BOSQUE. Другие пляжи не подменяют её статус.

- Цвет читается из изображения флага. При наличии подписи её цвет должен совпадать.
- Пустая строка — `no_report`, а не зелёный флаг.
- Ошибка сети, неизвестная картинка, исчезновение или дублирование строки — `unavailable`.
- Время запроса и время сообщения спасателей — разные поля.
- Ambumar может указывать только часы, без даты и часового пояса. Дата не выдумывается;
  рядом с флагом прямо сказано, что принадлежность сообщения сегодняшнему дню не подтверждена.
- Через 45 минут без свежей проверки или после смены местной даты карточка становится серой.
  Это технический срок устаревания нашего мониторинга, не гарантия актуальности флага
  и не норматив спасательной службы.
- Старый флаг не переносится в текущую карточку при ошибках и не сохраняется как разрешение.
- Прогноз AEMET доступен по ссылке, но не используется для вычисления разрешения купаться.
- Страница обозначена как личная, с данными спасателей. Она не является официальным сайтом.

## Проверка и локальный запуск (необязательно)

Из корня проекта:

```sh
python3 -m unittest discover -s tests -v
python3 scripts/collect.py
python3 -m http.server 8000 --directory site
```

Откройте http://localhost:8000/ . При открытии HTML двойным нажатием браузер может
запретить чтение JSON: это не тот же режим, что работа через вебхостинг.

Архив содержит стартовый JSON «нет данных», без вымышленного флага. Первый запуск
сборщика заменит его реальным ответом. `site/status.json` исключён из git, так как
это результат работы Actions. Не загружайте скрипты или Secrets в публичную папку сайта.

## Если что-то не работает

- `530` — проверьте FTP-логин и пароль.
- Ошибка сертификата — проверьте сервер из панели; не отключайте TLS.
- `550` при входе в каталог — неверный FTP-путь или недостаточно прав.
- `550` при переименовании — уточните поддержку замены файлов переименованием у провайдера.
- 404 на `/flag/` — каталог не находится в корне нужного домена либо отсутствует index.html.
- Страница работает, данные устарели — проверьте последние запуски Actions и квоту.
- Actions успешен, но данных нет — спасатели не опубликовали статус либо изменили таблицу.

## Проверено при подготовке

Пройдены тесты трёх цветов, пустой строки, отсутствующего пляжа, дубликата,
неизвестного изображения, противоречивой подписи и отсутствующего времени.
Проверены состояния устаревания в JavaScript и синтаксис встроенного скрипта.
Живой запрос к Ambumar выполнен. Визуальная проверка в удалённом браузере не состоялась:
он не смог открыть локальный адрес. Подключение FTPS и реальный запуск Actions требуют
ваших настроек и ещё не проверены.
